## Before Solving — Understanding the Problem

```
I have this leetcode problem: [paste problem].
Don't solve it. Just help me:
1. Identify edge cases I should consider
2. Clarify any ambiguity in the problem statement
3. Suggest what category/pattern this likely falls under
```

```
What are all the constraints I should pay attention to in this problem?
What do they imply about the expected time/space complexity?
[paste problem]
```

## Thinking Through Approach — Without Getting the Answer

```
I'm thinking of solving this with [approach e.g. sliding window / BFS / DP].
Is this the right direction? Don't give me the solution.
Just tell me if I'm on the right track and what I might be missing.
[paste problem]
```

```
Give me a hint for this problem — one small nudge, not the full solution.
I want to figure out the rest myself.
[paste problem]
```

## After Writing Your Solution — Review and Critique

```
Here is my solution to [problem name]:
[paste your code]

Review it for:
1. Correctness — are there edge cases it fails?
2. Time and space complexity — is my analysis right?
3. Can this be simplified without changing the approach?
Do NOT rewrite it for me yet.
```

```
My solution passes but is O(n²).
What's the bottleneck and what data structure or technique
could bring it down to O(n log n) or O(n)?
Don't give me the full optimized code yet.
[paste your code]
```

## When Stuck — Guided Hints (Not Full Solution)

```
I've been stuck on this for 20 minutes.
Give me a series of 3 progressive hints, from smallest to largest.
I'll stop reading when I have enough to continue.
[paste problem]
```

```
I understand the brute force O(n²) approach.
What's the key insight that makes the optimal solution possible?
One sentence only.
```

## After Seeing the Solution — Deep Understanding

```
I just read the editorial solution for [problem].
Explain WHY this approach works — not just what it does.
What's the core insight I should remember for similar problems?
```

```
What is the generalized pattern behind this problem?
Give me 3 other leetcode problems that use the exact same pattern
so I can practice it.
```

## For Interview Simulation

```
Act as a Google interviewer. Give me a medium-difficulty
graph problem. Ask follow-up questions as I explain my approach.
Push back if my reasoning is unclear. Don't give hints unless
I'm stuck for more than 5 minutes.
```

```
I just solved this problem in an interview setting.
[paste problem + your solution]

Grade my solution as a Google interviewer would:
- Did I handle edge cases?
- Was my communication clear?
- Would this pass Google's bar?
```

## When You Don't Understand an Algorithm

```
Explain [algorithm name e.g. Dijkstra's / KMP / Union Find] to me
like I've never seen it before.
Use a real-world analogy first, then walk through a small example
step by step. No code yet.
```

```
I read about [algorithm] but I don't intuitively understand WHY it works.
Don't explain what it does — explain why each step is necessary
and what breaks if you skip it.
```

## When You Don't Understand a Pattern

```
I keep seeing the "sliding window" pattern mentioned but I don't
know when to apply it vs two pointers.
Explain the difference with one example each.
When should I reach for one over the other?
```

```
What are the signs in a problem that tell me I should use [pattern]?
Give me a checklist I can use while reading a problem.
```

## When Code Makes No Sense to You

```
I'm looking at this code and I don't understand what it's doing:
[paste code]

Walk me through it line by line. For each line explain:
1. What it does
2. Why it's needed
3. What would break if it were removed
```

```
I understand each line individually but I don't see the big picture.
What is the overall strategy this code is implementing?
Describe it in 2-3 sentences without using code.
[paste code]
```

## When You Can't See the Connection to the Problem

```
I understand the algorithm in isolation but I can't see how it
applies to this problem. Bridge the gap for me — what property
of this problem makes [algorithm/pattern] the right tool?
[paste problem]
```

## Building Intuition for the Future

```
I just learned [pattern/algorithm]. Give me the simplest possible
problem that uses it — something where the pattern is obvious,
not hidden. I want to build intuition before tackling hard versions.
```

```
What are the 5 most important things to remember about [pattern]
when I'm under interview pressure and have 30 minutes to solve a problem?
```

---

## The Golden Rule

Always ask for **hints before solutions**. The moment you read a full solution, you lose the problem as a learning opportunity.

> "One hint only, then stop."

> "Tell me what I'm missing, not what to do."

> "Is my approach salvageable or fundamentally wrong?"
